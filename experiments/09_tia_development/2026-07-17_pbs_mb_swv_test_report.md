# PBS + Methylene Blue SWV Test Report

Date: 2026-07-17  
Project: NanoStat, nRF52840 + AD5941 electrochemical platform  
Test type: PBS + methylene blue probe sensor, single-frequency SWV blank/peak scan

## 1. Background

The purpose of this test session was to move from dummy-resistor validation into a real electrochemical liquid environment using PBS with a methylene blue (MB) probe sensor. Previous dummy-cell tests had already shown that the AD5941 sequencer, LPDAC waveform generation, FIFO capture, BLE/RTT data output, and potential-axis plotting pipeline were functional.

However, real PBS + MB measurements introduce a much more complex load than a pure resistor. The electrode/liquid interface includes solution resistance, double-layer capacitance, charge-transfer resistance, surface probe dynamics, and potentiostat loop settling. Therefore, a configuration that works well on a dummy resistor may fail or distort badly in liquid, especially at 150 Hz SWV.

Today's main question was:

Can the existing LPTIA path measure the 150 Hz MB SWV peak reliably, or should the high-frequency PBS/MB scan use the HSTIA path?

## 2. Experimental Context

### Electrode and electrolyte

- Electrolyte/test environment: PBS with MB probe sensor.
- External reference comparison: DropSens bench instrument was reported to produce a clean MB peak around approximately -200 mV with peak current around 200 nA.
- NanoStat measurement used the AD5941 internal sequencer to generate SWV and capture endpoint currents.

### Potential convention

The firmware now uses the electrochemical potential axis:

```text
WE(SE0) = VZERO
RE(RE0) = VBIAS
E_WE-RE = VZERO - VBIAS
```

The scan is therefore generated by changing the LPDAC 12-bit VBIAS code while holding VZERO at the 6-bit midpoint.

### Current convention

The final plotted and exported SWV differential current uses:

```text
Delta_I = I_forward - I_reverse
```

This matches the DropSens-style convention confirmed during the session.

For the HSTIA path, the raw ADC MUX polarity requires compensation. The ADI library's HSTIA RTIA calibration path measures `HSTIA_P - HSTIA_N` and then negates the RTIA voltage to match current direction. The firmware therefore applies a HSTIA-only current sign inversion before computing `Delta_I`, while leaving LPTIA unchanged.

## 4. Results

### HSTIA path, test `p`, 150 Hz

Two consecutive HSTIA scans were present in the RTT log. They produced very similar peak values.

| Run | Peak metric | Peak potential | Peak current |
|---|---|---:|---:|
| p run 1 | SG5, windowed | -256.781 mV | 527.244 nA |
| p run 2 | SG5, windowed | -256.781 mV | 531.202 nA |

Additional RTT observations:

- Capture size: 4119 FIFO samples per scan.
- HSTIA polarity compensation was explicitly enabled.
- Peak direction was positive after compensation.
- The repeated peak value differed by about 4 nA, under 1% relative difference.

Interpretation:

The HSTIA path produced a coherent SWV-like peak around -257 mV with good short-term repeatability. This is broadly consistent with the external DropSens observation of an MB peak in the -200 mV region, allowing for differences in electrode geometry, waveform implementation, peak processing, and reference/potential alignment.

### LPTIA path, test `l`, 150 Hz

The latest LPTIA scan, after reducing the internal RTIA to 160 kOhm and using an effective `160k || 2M = 148.148 kOhm`, still produced an abnormal large-current broad response.

From the plotted result provided during the session:

| Test | Peak potential | Apparent peak current | Visual behavior |
|---|---:|---:|---|
| l, LPTIA 160k||2M | about -101.0 mV | about 3929.8 nA | broad uA-level platform, not a clean MB peak |

Interpretation:

Lowering RTIA did not recover a clean peak. This argues against simple RTIA output saturation as the main root cause. With an effective RTIA of about 148 kOhm, a 3.9 uA interpreted current corresponds to roughly 0.58 V across the transimpedance path, which is large but not necessarily a hard ADC rail event. The problem is more likely dynamic: the LPTIA/LPPA low-power electrochemical loop is not settling cleanly in the real liquid/electrode system at 150 Hz.

## 5. Analysis

### Why dummy-resistor tests worked

The dummy resistor is close to a pure ohmic load. When the LPDAC voltage changes, the current changes almost immediately according to:

```text
I = V / R
```

This makes the dummy cell a good validation tool for:

- Sequencer timing.
- DAC code mapping.
- FIFO capture.
- ADC conversion.
- RTIA current scaling.
- Basic current polarity.

But it does not stress the full electrochemical control loop.

### Why PBS + MB is harder

The real electrode/liquid interface is not a pure resistor. It includes:

- Solution resistance.
- Double-layer capacitance.
- Charge-transfer resistance.
- Surface-bound MB redox dynamics.
- Diffusion/film transport.
- RE/CE/WE potentiostat loop dynamics.

At 150 Hz, the SWV half-period is only 3.33 ms. During each half-period, the system must apply the pulse, settle the control loop, allow capacitive current to decay, and sample the faradaic component near the pulse end. This is a demanding dynamic task.

### Why LPTIA likely failed

The LPTIA is optimized for low-power, low-noise measurements, not for fast real-liquid SWV dynamics. Even after lowering RTIA, the 150 Hz liquid measurement remained dominated by large background/platform behavior.

Likely contributors:

- LPTIA bandwidth and slew/settling limitations.
- LPPA control-loop settling limitations.
- Electrode double-layer charging current.
- The external 220 pF compensation capacitor and electrode capacitance shaping the transient response.
- Endpoint sampling still capturing residual capacitive current rather than mostly faradaic current.

The important observation is that lowering RTIA improved headroom but did not restore the correct waveform shape. This strongly suggests a dynamic-loop limitation rather than a simple gain-range problem.

### Why HSTIA performed better

The HSTIA path has higher bandwidth and a much smaller compensation capacitor. With 160 kOhm RTIA and 16 pF CTIA, it was able to produce a stable MB peak around -257 mV. The peak repeated within about 1% across two scans in the captured RTT log.

This suggests that for 150 Hz PBS + MB SWV, HSTIA is currently the more appropriate front-end path.

## 6. Current Conclusion

The current best interpretation is:

1. The firmware's potential axis and current polarity are now internally consistent:
   - `E_WE-RE = VZERO - VBIAS`.
   - `Delta_I = I_forward - I_reverse`.
   - HSTIA receives a sign correction before Delta extraction.

2. The HSTIA 160 kOhm path can produce a plausible and repeatable PBS + MB SWV peak at 150 Hz:
   - Peak around -256.8 mV.
   - Peak current around 527 to 531 nA.

3. The LPTIA path is not reliable at 150 Hz in real PBS + MB conditions:
   - Even after reducing effective RTIA to about 148 kOhm, it produced a uA-level broad response and an incorrect peak location.
   - This points to dynamic settling/control-loop limitations rather than simple ADC or RTIA saturation.

4. Dummy resistor success does not contradict the liquid failure:
   - The resistor validates the electrical/digital chain.
   - The liquid test exposes real electrochemical and potentiostat-loop dynamics.

## 7. Practical Recommendation

For subsequent PBS + MB and cortisol-sensor SWV work:

- Use HSTIA for high-frequency scans around 150 Hz.
- Keep LPTIA for low-frequency scans such as 10 Hz or 20 Hz, where the low-power/low-noise path may still be useful.
- If the KDM method needs both 150 Hz and 10 Hz scans, consider one of two strategies:
  - Use HSTIA for both frequencies to avoid cross-front-end calibration complexity.
  - Use HSTIA for the 150 Hz signal-on scan and LPTIA for the low-frequency scan only after a dedicated cross-calibration.

## 8. Next Steps

### Immediate experiments

1. Repeat `p` HSTIA 150 Hz at least 5 times without resetting the chemistry.
   - Record mean and standard deviation of peak current and peak voltage.
   - Confirm whether the about 530 nA peak is stable over time.

2. Run HSTIA at lower frequencies:
   - Suggested: 10 Hz, 20 Hz, 50 Hz, 100 Hz, 150 Hz.
   - Determine whether peak amplitude or potential shifts with frequency.

3. Run LPTIA only at lower frequencies:
   - Suggested: 10 Hz and 20 Hz first.
   - Check whether LPTIA recovers a clean MB peak when half-period is much longer.

4. Compare NanoStat HSTIA result against DropSens:
   - Same sensor.
   - Same PBS/MB condition.
   - Similar potential window and SWV amplitude if possible.
   - Record peak potential and peak current.

### Firmware/software improvements

1. Add run separation in the plot script and web app.
   - The current plot can appear as two layers if multiple RTT scans are pasted into the same file.
   - A `latest run only` option would avoid accidental overlay.

2. Add explicit first-N-point discard or edge-transient masking.
   - The current peak search window already excludes the extreme edge, but plots still show all data.
   - Display masking can make plots easier to interpret.

3. Add per-run statistics to the web app:
   - `I_peak_mean`
   - `I_peak_sd`
   - `V_peak_mean`
   - `V_peak_sd`
   - baseline sigma
   - SNR

4. Add an HSTIA option to the BLE `START,BLANK,<freq>` command.
   - At the moment, the web/BLE blank command should be checked carefully so the intended front-end is selected.

### Hardware/measurement considerations

1. Use battery-powered laptop or isolated measurement setup when possible.
2. Keep the small Faraday cover as a diagnostic aid, but do not assume it fully removes mains coupling.
3. Minimize exposed electrode and cable area.
4. Preserve HSTIA as the primary high-frequency front end for real-liquid SWV.

## 9. Thesis-Relevant Takeaway

This test provides an important engineering result:

The NanoStat platform can generate and acquire SWV waveforms in real PBS + MB conditions, but the choice of AFE path is critical. Dummy-cell validation alone is insufficient. In liquid, the LPTIA path is limited by dynamic electrochemical and control-loop behavior at 150 Hz, while the HSTIA path provides a more reliable high-frequency SWV response.

This supports a final architecture in which:

- LPTIA is used for low-frequency, low-noise or slow measurements.
- HSTIA is used for high-frequency SWV/KDM measurements.
- Sequencer-based waveform generation and endpoint post-processing remain the core acquisition method.
